# Order Payload Contract

This document records the current frontend/backend order payload contract. It is a documentation-only reference for refactors. Do not change the field names, HTML IDs, Apps Script function names, or Apps Script constants listed here unless the frontend, backend, spreadsheet tabs, Drive image handling, and manual tests are updated together.

The frontend submits `FormData` from `#orderForm` to the Apps Script web app. The backend reads scalar values from `e.parameter` and repeated checkbox values from `e.parameters`.

## 1. Common order fields

These fields are shared by every submitted order category.

| Field name | Source | Notes |
| --- | --- | --- |
| `orderCategory` | `#orderCategory`, overwritten during submit when the cart has items | Accepted backend values are `custom_cake`, `tasting_box`, `dessert`, and `batch_order`. The visible select only offers the first three; `batch_order` is generated by the submit handler when `cartItems.length > 0`. |
| `firstName` | `#firstName` | Trimmed by Apps Script. Defaults to `Unknown` if absent. |
| `lastName` | `#lastName` | Trimmed by Apps Script. Defaults to `User` if absent. |
| `phoneNumber` | `#phoneNumber` | Stored and included in notification email. |
| `email` | `#email` | Stored and included in notification email. |
| `deliveryOption` | `#deliveryOption` | Current values are `pickup` and `delivery`. |
| `pickupDate` | `#pickupDate` | Date string from the browser date input. |
| `paymentType` | `#paymentType` | Current values are `creditdebit` and `cashapp`. |
| `occasion` | `#occasion` | Required by the frontend. |
| `referralSource` | `#referralSource` | Optional. |
| `agreeRules` | `#agreeRules` | Frontend validation only. Apps Script does not read this field. |

Apps Script generates these values server-side and does not expect them from the frontend:

- `now`: timestamp for the sheet row.
- `orderId`: generated by `getNextOrderId(...)`, padded to three digits.
- `customerName`: sanitized from `firstName` and `lastName` for Drive image file names.

Every spreadsheet row begins with the shared columns in this order: timestamp, order ID, first name, last name, phone number, email, delivery option, pickup date, payment type, occasion, referral source.

## 2. Custom cake fields

Applies when `orderCategory` is `custom_cake`.

| Field name | Source | Notes |
| --- | --- | --- |
| `cakeType` | `#cakeType` | Current values are `heart`, `round`, and `tiered`. |
| `size` | `#size` | Dynamically populated from the selected cake type. |
| `flavor` | `#flavor` | Dynamically populated. |
| `frosting` | `#frosting` | Dynamically populated. |
| `filling` | `#filling` | Optional. Empty value is treated as no filling in the frontend display. |
| `addons` | `input[name="addons"]` checkboxes | Repeated field. Apps Script reads `e.parameters.addons` and joins selected values with `, `. |
| `clearBoxOption` | `#clearBoxOption` | Current values are `standard` and `clear`. Apps Script defaults to `standard`. |
| `cakeDetails` | `#cakeDetails` | Required by the frontend. |
| `notes` | `#notes` | Optional. |

Custom cake inspiration images are submitted with the top-level image field naming rules in section 6. The frontend requires at least one `inspirationPic` file for a standalone custom cake order.

The custom cake spreadsheet row appends these columns after the common fields: `cakeType`, `size`, `flavor`, `frosting`, `filling`, joined `addons`, `clearBoxOption`, `cakeDetails`, `notes`.

## 3. Tasting box fields

Applies when `orderCategory` is `tasting_box`.

| Field name | Source | Notes |
| --- | --- | --- |
| `tastingBoxType` | `#tastingBoxType` | Current values are `regular` and `deluxe`. |
| `regularBoxSideFillings` | dynamic checkboxes in `#regularFillingsContainer` | Regular box only. Repeated field. Frontend limits selection to two fillings. Apps Script joins selected values with `, `. |
| `tastingBoxNotes` | `#tastingBoxNotes` | Regular box notes. |
| `slice1Flavor` through `slice6Flavor` | dynamic selects in `#deluxeSlicesContainer` | Deluxe box source fields used by the frontend to build `deluxeSliceSummary`. Apps Script does not store these individual fields directly. |
| `slice1Frosting` through `slice6Frosting` | dynamic selects in `#deluxeSlicesContainer` | Deluxe box source fields used by the frontend to build `deluxeSliceSummary`. |
| `slice1Filling` through `slice6Filling` | dynamic selects in `#deluxeSlicesContainer` | Deluxe box source fields used by the frontend to build `deluxeSliceSummary`; filling can be empty. |
| `deluxeSliceSummary` | appended during submit | Deluxe box only. Newline-separated summary in the format `Slice N: flavor / frosting / filling`. This is the value stored by Apps Script. |
| `tastingBoxNotesDeluxe` | `#tastingBoxNotesDeluxe` | Deluxe box notes. |

Standalone tasting box orders do not submit inspiration image fields.

The tasting box spreadsheet row appends these columns after the common fields: `tastingBoxType`, joined `regularBoxSideFillings`, `deluxeSliceSummary`, selected notes.

## 4. Dessert fields

Applies when `orderCategory` is `dessert`.

| Field name | Source | Notes |
| --- | --- | --- |
| `dessertType` | `#dessertType` | Current values are `cupcakes`, `cake_cups`, `pretzel_rods`, and `cake_pops`. Apps Script maps these through `DESSERT_TYPE_LABELS`. |
| `dessertPackage` | `#dessertPackage` | Dynamically populated from `dessertType`. |
| `dessertFlavor` | `#dessertFlavor` | Used when enabled for the selected dessert type. |
| `dessertFrosting` | `#dessertFrosting` | Used when enabled for the selected dessert type. |
| `dessertFilling` | `#dessertFilling` | Optional for cupcakes. Other dessert types can send an empty value. |
| `dessertDetails` | `#dessertDetails` | Required by the frontend. |
| `dessertNotes` | `#dessertNotes` | Optional. |
| `dessertPriceEstimate` | appended during submit | Derived from `getDessertPackageDetails(dessertType, dessertPackage)`. |
| `dessertTotalPieces` | appended during submit | Derived from `getDessertPackageDetails(dessertType, dessertPackage)`. |

Dessert inspiration images are optional and use the top-level image field naming rules in section 6.

The dessert spreadsheet row appends these columns after the common fields: mapped dessert type label, `dessertPackage`, `dessertTotalPieces`, `dessertFlavor`, `dessertFrosting`, `dessertFilling`, `dessertDetails`, `dessertNotes`, `dessertPriceEstimate`.

## 5. Cart/batch order fields

Applies when the cart contains one or more items. The submit handler sets `orderCategory` to `batch_order` and sends the common fields plus these batch fields.

| Field name | Source | Notes |
| --- | --- | --- |
| `cartItemsJson` | appended during submit | JSON string from `cartItemJsonForSubmit()`. Apps Script parses it with `parseCartItemsJson(...)`. |
| `cartSummary` | appended during submit | Plain text summary from `buildCartPlainTextSummary()`. Apps Script uses the parsed JSON to rebuild a summary when possible and falls back to this value. |
| `cartItemCount` | appended during submit | String form of `cartItems.length`. Used by Apps Script to know how many item image field groups to scan. |

Each item in `cartItemsJson` currently has this shape:

```json
{
  "id": "cart-item-id",
  "orderCategory": "custom_cake | tasting_box | dessert",
  "displayCategory": "Custom Cake | Cake Tasting Box | Desserts",
  "title": "display title",
  "priceEstimate": "html or text estimate",
  "priceEstimateText": "plain text estimate",
  "requiredLeadDays": 7,
  "images": [
    {
      "name": "original-file-name.jpg",
      "type": "image/jpeg"
    }
  ],
  "details": {}
}
```

Important cart JSON rules:

- `cartItemsJson.images` contains only image metadata (`name` and `type`). Base64 image bytes are not stored in the JSON payload.
- Batch image bytes are submitted as separate `item{itemNumber}Image{imageNumber}` fields, documented in section 6.
- Custom cake cart item `details` can include `cakeType`, `cakeTypeValue`, `size`, `flavor`, `frosting`, `filling`, `addons`, `clearBoxOption`, `cakeDetails`, and `notes`.
- Regular tasting box cart item `details` can include `tastingBoxType`, `includedFlavors`, `frosting`, `sideFillings`, and `notes`.
- Deluxe tasting box cart item `details` can include `tastingBoxType`, `deluxeSlices`, `deluxeSliceSummary`, and `notes`.
- Dessert cart item `details` can include `dessertType`, `dessertTypeValue`, `dessertPackage`, `totalPieces`, `flavor`, `frosting`, `filling`, `dessertDetails`, `notes`, and `priceEstimate`.

The batch spreadsheet row appends these columns after the common fields: `cartItemCount`, rebuilt or fallback `cartSummary`, raw `cartItemsJson`.

## 6. Image field naming rules

Standalone custom cake and dessert submissions use top-level image fields:

| Field pattern | Notes |
| --- | --- |
| `image1`, `image2`, `image3` | Base64 image bytes without the `data:mime/type;base64,` prefix. |
| `imageName1`, `imageName2`, `imageName3` | Original file names. Apps Script requires both image bytes and image name before saving a file. |
| `imageType1`, `imageType2`, `imageType3` | MIME type. Apps Script defaults to `image/jpeg` when absent. |

Batch/cart submissions use item-scoped image fields:

| Field pattern | Notes |
| --- | --- |
| `item{itemNumber}Image{imageNumber}` | Base64 image bytes. `itemNumber` is one-based cart position. `imageNumber` is one through three. |
| `item{itemNumber}ImageName{imageNumber}` | Original file name for the matching image. |
| `item{itemNumber}ImageType{imageNumber}` | MIME type for the matching image. Defaults to `image/jpeg` when absent. |

Frontend source file inputs:

- Custom cake files use `input[name="inspirationPic"]`.
- Dessert files use `input[name="dessertInspirationPic"]`.
- Both flows limit submitted images to the first three files/inputs.

Apps Script image handling rules:

- `saveInspirationImages(...)` scans `image1` through `image3`.
- `saveBatchInspirationImages(...)` scans `item1Image1` through `item{cartItemCount}Image3`.
- `cleanFileName(...)` replaces whitespace with underscores and removes characters outside `[\w.\-]`.
- Standalone saved file names follow `{customerName}_{orderId}_inspo{imageNumber}_{safeImageName}`.
- Batch saved file names follow `{customerName}_{orderId}_item{paddedItemNumber}_inspo{imageNumber}_{safeImageName}`.

## 9. Manual order-flow test cases

Run these after any payload, form, or Apps Script refactor.

1. Standalone custom cake, single image
   - Select `custom_cake`, choose a non-tiered cake type, fill all required custom cake and common fields, upload one inspiration image, agree to policies, and submit.
   - Expected: Apps Script returns success, a row is appended to `Custom Orders`, one Drive file is saved from `image1`, and the notification email contains the custom cake details.

2. Standalone custom cake, three images
   - Repeat the custom cake flow with three inspiration images.
   - Expected: `image1` through `image3` are posted with matching `imageNameN` and `imageTypeN`; all valid images are saved.

3. Tiered cake lead-time validation
   - Select `custom_cake` with `cakeType=tiered`, choose a date earlier than the required tiered lead time, and try to continue or submit.
   - Expected: frontend blocks the flow with the lead-time message and does not submit. A valid later date should submit normally.

4. Regular tasting box
   - Select `tasting_box`, choose `regular`, select zero, one, and two side fillings in separate test runs, add notes, fill common fields, and submit.
   - Expected: a row is appended to `Tasting Box Orders`; `regularBoxSideFillings` is joined correctly; no image fields are required.

5. Deluxe tasting box
   - Select `tasting_box`, choose `deluxe`, fill all six slice flavor/frosting fields and optional fillings, add notes, and submit.
   - Expected: `deluxeSliceSummary` is appended and stored; individual slice fields can exist in the form payload but the backend uses the summary.

6. Dessert without images
   - Select `dessert`, choose each dessert type in separate runs, pick a package, fill required details and common fields, and submit without inspiration images.
   - Expected: a row is appended to `Dessert Orders`; `dessertPriceEstimate` and `dessertTotalPieces` are present when package details exist; no Drive image is required.

7. Dessert with images
   - Submit a dessert order with one to three optional inspiration images.
   - Expected: the images use `imageN`, `imageNameN`, and `imageTypeN` and are saved by `saveInspirationImages(...)`.

8. Mixed cart checkout
   - Add a custom cake with images, add a regular or deluxe tasting box, add a dessert with an image, then checkout.
   - Expected: submit payload has `orderCategory=batch_order`, includes `cartItemsJson`, `cartSummary`, `cartItemCount`, and item-scoped image fields. A row is appended to `Batched Orders`; images are saved with `item01`, `item02`, etc. file name segments.

9. Cart edit and remove
   - Add multiple items, edit one, remove one, then checkout.
   - Expected: `cartItemCount`, `cartItemsJson`, `cartSummary`, and item image field numbering match the final visible cart order.

10. Required field and policy validation
    - Attempt submit with missing order details, missing common contact fields, missing custom cake image, and unchecked `agreeRules`.
    - Expected: frontend blocks the flow before posting to Apps Script.

11. Image limit behavior
    - Try adding more than three custom cake or dessert image inputs, and try cart checkout with more than three saved images on an item.
    - Expected: only the first three images for that standalone order or cart item are submitted and scanned by Apps Script.

12. Apps Script error handling
    - Test with a temporary invalid deployment or backend failure in a non-production environment.
    - Expected: frontend shows the submission failure status; no cart is cleared unless the fetch succeeds.
